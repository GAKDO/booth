# 조사: BO1 촬영 도구

## 1. 운영 화면

- **결정**: 표준 라이브러리 `http.server.ThreadingHTTPServer`로 JSON API와 정적 HTML 한 장을 띄운다. 기본 포트 8320, 같은 네트워크(또는 Tailscale)의 태블릿에서 연다.
- **이유**: 명확화에서 태블릿·모니터 둘 다 열 수 있는 웹 화면으로 정했다. 화면은 단계 안내·버튼·미리보기·대기열 수 정도라 프레임워크가 필요 없고, Jetson에 설치할 것이 줄어든다.
- **검토한 대안**: Flask·FastAPI(의존성 추가, 이득 적음), OpenCV 창(태블릿에서 못 엶), 터미널(사진 확인 불가).

## 2. 카메라 두 대 찍기

- **결정**: 단계마다 CAM1을 열어 몇 프레임 버리고(노출 안정) 한 장 찍고 닫은 뒤 CAM2를 같은 방식으로. 장치는 `/dev/v4l/by-id/` 경로로 고정해 CAM1·CAM2가 바뀌지 않게 한다.
- **이유**: README "막힐 때"가 두 대를 동시에 고해상도로 받지 말고 번갈아 찍으라고 한다. USB 대역폭 문제를 피한다.
- **검토한 대안**: 두 대 상시 스트리밍(대역폭·발열), `/dev/videoN` 번호(재부팅 때 바뀜).

## 3. 카메라 고정 설정

- **결정**: 조명마다 `exposure_time_absolute`·`white_balance_temperature`·`focus_absolute`(자동 끔)를 JSON 설정 파일(`TRACE_BOOTH_PRESETS`)에 두고, 찍기 직전에 `v4l2-ctl -d <장치> -c ...`로 적용한다. 적용한 값은 사진 기록에 남긴다.
- **이유**: 설계서가 "v4l2-ctl 고정 설정"이고, README가 조명마다 수동 값을 정해 저장하라고 한다. 값은 부스 설정 날 실측하므로 코드에 넣지 않는다.
- **남은 것**: `capture/README.md`(설정 방법·확인 6가지)가 아직 없다. quickstart에 측정 절차를 두고, 실측 뒤 설정 파일 예시를 채운다.

## 4. 로컬 기록과 재시도

- **결정**: 사진 파일을 먼저 디스크에 쓰고 `fsync`, 그다음 SQLite에 `shot` 행(상태 `PENDING`)을 넣는다. 업로더 스레드가 `PENDING`·`FAILED`를 오래된 순으로 올리고, 실패하면 지수 백오프(2·4·8…최대 60초). 도구를 다시 켜면 남은 행부터 이어 간다.
- **이유**: 표준 라이브러리로 껐다 켜도 남는 대기열을 만들 수 있다. 파일을 먼저 쓰므로 기록만 있고 파일이 없는 경우가 없다.
- **검토한 대안**: 폴더 이동 방식(상태·사유를 남기기 어려움), RabbitMQ(부스에 과함).

## 5. 중복 업로드

- **결정**: 올리기 전에 `head_object`로 같은 키가 있는지 보고, 메타데이터 `sha256`이 같으면 완료로 처리, 다르면 덮어쓰지 않고 `CONFLICT`로 남긴다.
- **이유**: 수용 시나리오 "같은 이름·같은 해시 파일 하나만 남는다"와 헌법 III(덮어쓰지 않음). `trace-raw`는 버전 관리도 켜져 있다(킥오프 계획).

## 6. 파일명·키

- **결정**: 파일명 `{기기ID}_{면}_{조명}_{카메라}_{번호}.jpg`(킥오프 계획). 번호는 같은 기기·면·조명·카메라 안에서 01부터, 재촬영 때 하나씩 올린다. `trace-raw` 키는 `{기기ID}/{파일명}`. SLATE는 면 코드가 아니므로 `{기기ID}/slate/{기기ID}_SLATE_CAM1_{번호}.jpg`로 학습 데이터 모드에서만 올린다.
- **이유**: 파일명만으로 기기·면·조명·카메라를 알 수 있고, 기기별 폴더라 Label Studio·데이터셋 빌더가 기기 단위로 나누기 쉽다(ML1).
- **확인 필요**: SLATE 경로는 계약 값이 아니라 저장 위치 약속이다. ML3·ML1 담당(A)과 맞춘다.

## 7. 기기 ID

- **결정**: `^[A-Z]{2,4}[0-9]{2}$`(예: MB01, REG01).
- **확인 필요**: `devices.csv`가 레포에 없다. 실제 파일을 받으면 형식을 다시 확인한다.

## 8. 출고·반납 모드 (스토리 3)

- **결정**: contracts C1(11/3) 고정 뒤 계획을 보완한다. BOOTH client 자격 → JWT → `POST /captures/sets`(사진별 sha256) → URL로 PUT → `complete`. URL이 만료되면 세트 URL을 다시 받는다.
- **막힌 점**: plan.md "계약 확인 필요" 2건.
